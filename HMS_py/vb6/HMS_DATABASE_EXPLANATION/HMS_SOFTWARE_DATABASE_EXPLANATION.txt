================================================================================

DATABASE NAME: SunshineData2526
TOTAL TABLES: 271
SOFTWARE: Hotel Management System (HMS)
PURPOSE: Complete hotel operations management

================================================================================
                    DATABASE STRUCTURE OVERVIEW
================================================================================

The HMS database is organized into the following major modules:

1. USER MANAGEMENT SYSTEM (8 tables)
2. ROOM MANAGEMENT SYSTEM (15 tables)
3. BOOKING & RESERVATION SYSTEM (25 tables)
4. GUEST MANAGEMENT SYSTEM (30 tables)
5. FINANCIAL & ACCOUNTING SYSTEM (40 tables)
6. RESTAURANT & FOOD SERVICE SYSTEM (35 tables)
7. HOUSEKEEPING SYSTEM (20 tables)
8. INVENTORY & STORE MANAGEMENT (25 tables)
9. REPORTING & ANALYTICS SYSTEM (30 tables)
10. ADMINISTRATION & CONFIGURATION (43 tables)

================================================================================
                    1. USER MANAGEMENT SYSTEM
================================================================================

PURPOSE: Manage user authentication, permissions, and access control
OUTLET: Front Office, Back Office, Administration

1.1 UserMast Table
------------------
PURPOSE: Master user authentication and profile data
WORKING: 
- Stores all user login credentials with encrypted passwords
- Manages user roles, permissions, and access levels
- Controls system access based on user rights
DATA FLOW:
- Login Form → UserMast (Validate credentials) → Session Creation
- User Registration → UserMast (INSERT new user)
- User Update → UserMast (UPDATE user details)
- User Deactivation → UserMast (UPDATE ActiveYN = 'N')
KEY FIELDS:
- USER_NAME: Login username (Primary Key)
- PASSWD: Encrypted password
- LABEL: User role/level (1=Admin, 2=Manager, 3=Staff, etc.)
- ShortName: Display name
- ActiveYN: Active status ('Y'/'N')
- BackColor: UI theme color

1.2 User1 Table
---------------
PURPOSE: Extended user personal information
WORKING:
- Stores personal details like address, phone, email
- Extends UserMast with contact information
- Used for user profile management
DATA FLOW:
- User Registration → UserMast → User1 (INSERT personal info)
- Profile Update → User1 (UPDATE contact details)

1.3 User2 Table
---------------
PURPOSE: Additional user preferences and settings
WORKING:
- Stores user preferences, language settings
- UI customization options
- Notification preferences
DATA FLOW:
- User Settings → User2 (UPDATE preferences)

1.4 User_Module Table
--------------------
PURPOSE: Module-wise permissions for users
WORKING:

- Role-based access control implementation
- Permission inheritance management
DATA FLOW:
- Permission Assignment → User_Module (INSERT/UPDATE)
- Access Check → User_Module (SELECT permissions)

1.5 UserPermission Table

1.6 UserCollection Table
