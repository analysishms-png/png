================================================================================
                            STORED PROCEDURES REPLACEMENT
================================================================================

SQLite does not support stored procedures. Use PHP functions instead:

SQL Server Stored Procedure:
CREATE PROCEDURE sp_GetUserDetails
    @UserName varchar(50)
AS
BEGIN
    SELECT USER_NAME, ShortName, LABEL 
    FROM UserMast 
    WHERE USER_NAME = @UserName AND ActiveYN = 'Y'
END

SQLite PHP Function Replacement:
<?php
function getUserDetails($conn, $userName) {
    $stmt = $conn->prepare("SELECT USER_NAME, ShortName, LABEL 
                           FROM UserMast 
                           WHERE USER_NAME = ? AND ActiveYN = 'Y'");
    $stmt->execute([$userName]);
    return $stmt->fetch();
}
?>

SQL Server Trigger to SQLite Trigger:

SQL Server:
CREATE TRIGGER tr_UpdateRoomStatus
ON RoomMast
AFTER UPDATE
AS
BEGIN
    IF UPDATE(RoomStat)
    BEGIN
        INSERT INTO RoomLog (RoomCode, OldStatus, NewStatus, UpdateTime)
        SELECT i.Code, d.RoomStat, i.RoomStat, GETDATE()
        FROM inserted i
        JOIN deleted d ON i.Code = d.Code
    END
END

SQLite:
CREATE TRIGGER tr_UpdateRoomStatus
AFTER UPDATE ON RoomMast
WHEN NEW.RoomStat <> OLD.RoomStat
BEGIN
    INSERT INTO RoomLog (RoomCode, OldStatus, NewStatus, UpdateTime)
    VALUES (NEW.Code, OLD.RoomStat, NEW.RoomStat, datetime('now'));
END;

================================================================================
                            QUERY CONVERSION
================================================================================

SQL Server to SQLite Query Conversion:

1. TOP vs LIMIT:
---------------
SQL Server: SELECT TOP 10 * FROM UserMast WHERE LABEL = 1 ORDER BY USER_NAME
SQLite: SELECT * FROM UserMast WHERE LABEL = 1 ORDER BY USER_NAME LIMIT 10

2. GETDATE() vs datetime():
---------------------------
SQL Server: SELECT GETDATE()
SQLite: SELECT datetime('now')

3. DATEADD():
-----------
SQL Server: DATEADD(day, 7, GETDATE())
SQLite: datetime('now', '+7 days')

4. CONVERT():
-----------
SQL Server: CONVERT(varchar(10), GETDATE(), 120)
SQLite: strftime('%Y-%m-%d', 'now')

5. ISNULL():
----------
SQL Server: ISNULL(ShortName, 'Unknown')
SQLite: COALESCE(ShortName, 'Unknown')

6. LEN():
--------
SQL Server: LEN(ShortName)
SQLite: LENGTH(ShortName)

--------------------------
<?php
// backend/login_sqlite.php
require_once 'config/database_sqlite.php';

$database = new DatabaseSQLite();
$conn = $database->getConnection();

$username = $_POST['username'];
$password = $_POST['password'];

try {
    $stmt = $conn->prepare("SELECT USER_NAME, PASSWD, LABEL, ShortName FROM UserMast WHERE USER_NAME = ? AND ActiveYN = 'Y'");
    $stmt->execute([$username]);
    $user = $stmt->fetch();

        $_SESSION['username'] = $user['USER_NAME'];
        $_SESSION['role'] = $user['LABEL'];
        $_SESSION['display_name'] = $user['ShortName'];
        $_SESSION['logged_in'] = true;
        
        echo json_encode(['status' => 'success', 'message' => 'Login successful']);
    } else {
        echo json_encode(['status' => 'error', 'message' => 'Invalid credentials']);
    }
} catch(PDOException $e) {
    echo json_encode(['status' => 'error', 'message' => 'Database error']);
}

================================================================================
                            PERFORMANCE OPTIMIZATION
================================================================================

1. Indexing Strategy:
-------------------
- Add indexes to frequently queried columns
- Use composite indexes for multi-column queries
- SQLite automatically creates indexes for PRIMARY KEY

2. Query Optimization:
--------------------
- Use prepared statements
- Avoid SELECT *
- Use LIMIT for large result sets
- Use appropriate data types

3. Database Maintenance:
----------------------
- Use VACUUM to optimize database file
- Use ANALYZE to update statistics
- Consider WAL mode for better concurrency

4. Connection Management:
-----------------------
- Keep connections open for multiple queries
- Use connection pooling if needed
- Close connections when done

================================================================================
                            SECURITY CONSIDERATIONS
================================================================================

1. File Security:
---------------
- Set appropriate file permissions
- Store database outside web root
- Use file encryption if needed

2. Input Validation:
------------------
- Use prepared statements
- Validate all user inputs
- Sanitize inputs before queries

3. Password Security:
-----------------
- Use password_hash() for password storage
- Implement password policies
- Consider database encryption

4. Access Control:
---------------
- Implement role-based access control
- Validate user permissions
- Log all database operations
