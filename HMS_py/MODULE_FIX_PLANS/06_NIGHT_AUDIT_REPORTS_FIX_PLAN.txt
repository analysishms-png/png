NIGHT AUDIT AND REPORTS FIX PLAN
================================

VB6 logic extracted from legacy reporting flow:
- NightAuditRR_Click uses numeric/hex cases 0..&HC to choose report families.
- MatRep_Click uses an index-based Select Case to open the correct report in rInventRepView.
- MatVatR_Click uses 0, &HA, &HB, &HC, &HD, &HE, &H10 patterns to choose VAT-related report screens.
- Night audit posting checks environment flags, pending KOTs, unsettled bills, and posts room charges/POS revenue.

Scope:
- Night audit posting logic
- Report mapping and output generation
- Revenue analysis / VAT / material report indexes
- PDF generation and report naming

Primary Files:
- HMS_py/core/nightaudit.py
- HMS_py/core/reports.py
- HMS_py/ui/pos_na.py
- HMS_py/ui/general_setup_ui.py

Crystal / print pages and names:
- NightAuditRR_Click / NightAuditLR / frmReNightAudit / FrmNAMessageA / FrmNAMessageB / FrmNAMessageC
- rFomRepView / Daily Report / Daily Report-II / RevAnalysis / GuestTrialBalance / NightAuditReportI
- OccAnalysis / MarketSegAnalysis / BusinessAnalysis / CompanyAnalysis / TravelAgentAnalysis / FOCC Report / Food Cost / FBCostStatement
- Material report page names: MatRep_Click -> PurchaseReg, PurchaseSumm, CashCreditPurch, StockRegStore, StockSummStore, StoreIssReg, DailyStoreIssRpt, PurchaseLedger, IssueReg, StoreIssueReport
- VAT report page names: MatVatR_Click -> VATRegister, VATRegisterII, VATRegisterIII, Form24AnnexureA, FormIII, UPVATXXIV
- Temp printing setup: report/temp path and print preview modules tied to Analysis.ini + Enviro values

VB6 behavior to preserve:
1. Report dispatch by index must match the exact VB6 case mapping.
2. The report names and form targets are the real contract, not arbitrary Python names.
3. Night audit should be cumulative and idempotent for already-posted rows.
4. When DB data is absent, the function should still return valid mapping metadata rather than crash.

Known Missing / Risky Logic:
1. Legacy VB6 index mapping uses hex values; some Python mapping misses execution of mapped lambdas.
2. Some reports are mode/flag dependent and require exact VB6 case mapping.
3. POST operations in night audit must be idempotent for repeated runs.
4. PDF generation may not exactly match VB6 report formatting, but should remain stable and readable.
5. Some report cases are placeholder-only and need a documented safe fallback behavior.

Required Fixes:
1. Ensure all VB6 hex-based cases resolve correctly to report metadata.
2. Use fallback metadata when DB is unavailable, rather than raising or returning unknown.
3. Make night audit posting skip already-posted rows and only act on valid dates.
4. Protect report functions by returning explicit mapping metadata with no fake DB assumptions.
5. Document which reports remain read-only and which are live-query-backed.

Implementation Steps:
1. Re-check all index mappings for night audit and material/VAT report cases.
2. Fix callable execution and fallback data in report handlers.
3. Add regression tests covering:
   - 0x0A mapping
   - material report 0x0A mapping
   - VAT register 0x0A mapping
   - duplicate posting skip
4. Run focused tests before release.

Expected Result:
- VB6-style report indexes are mapped correctly.
- Night audit remains safe and not duplicated on rerun.
- Reports are deterministic and support no-DB read-only fallback.
