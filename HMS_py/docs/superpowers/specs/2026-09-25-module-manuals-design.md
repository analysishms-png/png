# HMS_py — Module-Wise Manual + Test + Screenshot Pipeline (Design Spec)

**Date:** 2026-09-25
**Status:** Approved (conversational design approval)
**Scope:** Pilot = Front Office; then all 14 modules via frozen template.

## 1. Goal

Har HMS module ke liye ek complete, verifiable package:

1. **Run + Test proof** — 4-layer test run ka log.
2. **Module manual** — DB workflow + MenuHelp-based Master/Operations/Reports split + frontend (PyQt6) + backend (`core/*.py`) logic.
3. **Screenshots** — live Python app se capture kiye gaye.
4. **Reusable instruction template** — jisse aage sab manuals banenge.

**Success criteria:** sab tests green (ya documented known-failures), har module folder me required files present, screenshots non-blank + OCR-legible, pilot user-approved before batch phase.

## 2. Decisions (user-confirmed)

| Decision | Choice |
|---|---|

## 4. Pipeline tooling (`HMS_py/tools/manual_pipeline/`)

| Script | Responsibility | Output |
|---|---|---|
| `capture_module.py` | Launch `python -m HMS_py.main` with `HMS_GUI=1`, login `KK/kanpur` (from `_qa/login_creds.json`), navigate module (Alt+keys / sidebar dispatcher), find PyQt6 window via win32gui, capture via PIL `ImageGrab`, verify non-blank via pixel-variance check | `screenshots/*.png` + `manifest.json` |
| `collect_logic.py` | Read `menuHelp` (Option, Flag, Opt1-4, Module_Name, OutletCode) for module + read code (`core/*`, `ui/shell.py` registry) to map forms/functions/tables | `<module>/_logic.json` |
| `run_module_tests.py` | Run L1 unit / L2 database / L3 UI tests with module-relevant `-k` filters; capture pass/fail/skip + duration | `TEST_RESULTS.md` |

Safety rules:
- DB tests: only run existing test suite (fixture rollback assumed; verify one file for transaction usage before batch).
- Capture script is **read-only navigation** — never clicks Save/Add in forms.
- Stale `Analysis.ini` paths (LENOVO) → non-fatal (`db.ensure_paths()` best-effort); if reports/temp dirs required, create local equivalents and log.

## 5. Testing strategy (4 layers)

| Layer | Scope | Command |
|---|---|---|
| L1 Unit | no DB | `python -m pytest tests/unit -q` → **284/284 baseline** |
| L2 Live DB | transactions, SQL | `python -m pytest tests/database -q` |
| L3 UI | widget instantiation (offscreen) | `pytest tests/test_wave_ui_forms.py tests/test_ui_walkthroughs.py` |
| L4 Live walkthrough | real window + OCR sanity | `capture_module.py` |

Results feed `00_GLOBAL/RUN_TEST_LOG.md` + per-module `TEST_RESULTS.md`. Known baseline failures documented, not silently skipped.

## 6. Pilot flow (Front Office)

1. **Phase 1 — Test run:** L1–L3 execute; log to `RUN_TEST_LOG.md`.
2. **Phase 2 — Logic collect:** `collect_logic.py --module FrontOffice` → `_logic.json` (MenuHelp rows + code map).
3. **Phase 3 — Screenshots:** live app → shell FO view + key FO forms (Booking, Check-In, Folio, Check-Out) + Masters/Operations/Reports split shots.
4. **Phase 4 — Manual:** write README/DATABASE/FRONTEND/BACKEND/TEST_PLAN using `00_Instructions/MANUAL_TEMPLATE.md`.
5. **Gate — user review/approval.**
6. **Phase 5 — Batch:** freeze template; loop 13 remaining modules (same 4 phases each).

## 7. Risks & mitigations

| Risk | Mitigation |
|---|---|
| PyQt6 live window capture fails (DPI, window not found) | fallback: `widget.grab()` offscreen snapshot; log which method used |
| Login flow differs (company select step) | reuse `_run_hms.py`/shell flow knowledge; creds from `_qa/login_creds.json` |
| Blank screenshots (seen in `_qa/kanpur_12..17.png` = 107 B) | pixel-variance validation step; fail loud, recapture |
| Live DB writes during tests | inspect test fixtures for rollback first; run L2 on transaction-wrapped tests only |
| Finance Alt+F navigation known-broken | documented in QA history; navigation via sidebar click instead of Alt key |
| Stale Analysis.ini paths | local path overrides + log |
