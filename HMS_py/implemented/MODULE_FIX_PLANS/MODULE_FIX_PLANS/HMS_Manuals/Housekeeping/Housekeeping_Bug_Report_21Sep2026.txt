2. BUG LIST (SEVERITY-WISE)
--------------------------------------------------------------------------------

=== CRITICAL ===

[BUG-01] Business Date Stale Hai - Saare Naye Vouchers Galat Date Par Banenge
  Screen   : Header (saare screens) + Start Cleaning + Laundry Send
  Kya hua  : Header me business date 17-Sep-2026 dikhta hai jabki aaj
             21-Sep-2026 hai. Start Cleaning form aur Laundry Send form
             dono me date field 17-Sep-2026 default me aati hai.
  Impact   : 17 se 21 tak jo bhi cleaning/laundry/stock entries bani hain
             wo 17-Sep ki date par record hui hongi. Reports me date filter
             lagaoge to data galat date bucket me jayega. Night Audit ke
             bina date roll-forward hua ya nahi, verify karna hoga.
  Repro    : Login karo -> header date dekho (17-Sep-2026) vs system date
             (21-Sep-2026). Phir Operations > Start Cleaning kholo -> date
             field me bhi 17-Sep-2026.
  Root Cause (code) : Controller ka session 'ncurdate' stale hai. Voucher
             creation me bhi yahi use hota hai.
  Fix      : Business date ko Night Audit ke saath auto-roll karo, ya
             session expiry par re-init karo. Header me stale date par
             warning banner dikhao.
  Evidence : _bugtest/sc_after.png, _bugtest/ls_after.png

[BUG-02] Negative Stock Allowed - Stock Minus Me Ja Sakta Hai
  Screen   : Reports > HK Stock Report
  Kya hua  : Coffee item ka Opening -45, Closing -52 hai. Floor Cleaner
             -4.74, Glass Cleaner -2.87. System ne stock minus me hone ke
             bawajood 7 unit aur issue kar di (HKISS-34 se HKISS-39).
  Impact   : Data integrity issue. Stock valuation reports me negative
             values aayengi. Audit me problem hogi.
  Repro    : Reports > HK Stock Report -> 01-Sep se 21-Sep -> Refresh ->
             Coffee group dekho (Opening -45.000, Bal -52.000).
  Root Cause (code) : HouseKeeping.php (cleaning completion me HKISS stock
             voucher banne wale block) me available-qty check NAHI hai.
             Amenities qty directly stock issue ho jati hai chahe stock
             0 se neeche chala jaye. Issue/save transactions me bhi koi
             stock validation nahi mili.
  Fix      : Stock issue par available qty check + blocking warning dalo.
             Existing negative balances ke liye ek data-fix/adjustment
             entry ka plan banao.
  Evidence : _bugtest/hks_data.png (screenshot me 3 negative items)

=== HIGH ===

[BUG-03] Ek Room Do Housekeepers Ko Assign Ho Jata Hai (Duplicate Assignment)
  Screen   : Operations > Room Status Board (Pending Inspections panel)
  Kya hua  : Room 103 ke 2 assignments dikhe - ek DEMO housekeeper ko,
             ek dusre housekeeper ko. Same room pehle se assigned ho to
             system rokta nahi.
  Impact   : 2 housekeepers same room clean karenge. Inspection 2 baar
             trigger hoga. Accountability confuse hogi.
  Extra Note (code) : Cleaning complete hone par status update ROOM par
             hota hai (assno ignore karke, 'cleaningstatus=In Progress'
             wali saari rows) - matlab duplicate assignments me dono
             entries ek saath complete ho jayengi. Code comment khud
             accept karta hai ki assno common hai.
  Repro    : Operations > Start Cleaning -> Room 103 ko 2 alag
             housekeepers ko assign karo -> dono save ho jate hain ->
             Room Status Board me Room 103 2 baar dikhega.
  Fix      : Room level par active assignment uniqueness check (DB
             constraint ya controller me check). Ek room ka ek hi active
             assignment ho.
  Evidence : Room Status Board screenshot (Room 103 duplicate)

[BUG-04] Cleaning Type Master - Bina Department Submit Karne Par RAW SQL Error
  Screen   : Masters > Cleaning Type
  Kya hua  : Cleaning Type name bhar ke, department select kiye bina
             submit kiya to user ko poora raw database error dikhta hai:
             "SQLSTATE[23000]: Integrity constraint violation: 1048
             Column 'dcode' cannot be null"
  Impact   : Unprofessional error exposure. Internal DB schema user ko
             dikhta hai. Security bad practice.
  Repro    : Masters > Cleaning Type -> Name bharo -> Department khali
             chhodo -> Save -> raw SQL error screen par.
  Root Cause (code) : Controller me server-side validation missing hai -
             'dcode' required mark nahi hai; DB constraint seedha fail
             hota hai aur error user tak pahunch jata hai.
  Fix      : Request validation me 'dcode => required' + friendly error
             message. Global exception handler me validate errors ko
             proper JSON/alert me convert karo.
  Evidence : _bugtest/ct_state.txt (error text captured)

[BUG-05] HK Report Me Past-Departure Guests "In-House" Dikh Rahe Hain
  Screen   : Reports > Housekeeping Report
  Kya hua  : Jinka checkout/departure 16-18 Sep ko ho chuka hai, wo aaj
             21-Sep ko bhi report me in-house/inventory me dikhte hain.
             Report me departure date ka filter shayad hi lag raha ho.
  Impact   : Housekeeping team un rooms ko bhi clean karne jayegi jo
             actually khali/check-out ho chuke hain. Priority galat
             set hogi.
  Repro    : Reports > Housekeeping Report -> 01-Sep se 21-Sep range ->
             past departure dates wale guests abhi bhi list me.
  Fix      : Query me departure date / in-house status ka proper filter
             lagao. Sirf aaj ke staying guests + due-out dikhao.
  Evidence : _bugtest/hkr.png

[BUG-06] Laundry Send - Submit Par Silent Failure + Unrelated Support Modal
  Screen   : Operations > Laundry Send
  Kya hua  : Form bhar ke submit kiya (2 attempts) - na success message,
             na error message, na data save (Send No. wapas LAISS0005 par
             hi raha). Sath hi submit karte hi support-ticket modal khul
             gaya jo is form se koi lena-dena nahi hai.
  Impact   : User ko pata hi nahi chalta ki entry save hui ya nahi.
             Laundry contractor challan track nahi hoga. Support modal
             auto-open user ka form bhulne par majboor karta hai.
  Repro    : Operations > Laundry Send -> Send Date, Sent By, Challan No,
             qty bharo -> Send -> kuch nahi hota + support modal khul
             jata hai. Send No. next number par advance nahi hota.
  Possible Cause : Client-side JS me submit handler kisi condition
             (qty/stock/precondition) par chupchaap return kar raha hai,
             aur ticket-widget ka trigger galat element par bound hai.
  Fix      : (1) Submit handler har failure path par user-visible error
             de. (2) Support widget ka event binding theek karo.
             (3) Voucher prefix missing ho to clear message de (code me
             prefix-check hai par user tak nahi pahunch raha).
  Evidence : _bugtest/ls2.txt, _bugtest/ls4.txt (Send No. unchanged),
             screenshots ls_after.png
