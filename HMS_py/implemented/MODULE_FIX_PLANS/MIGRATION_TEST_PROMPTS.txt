================================================================================
MIGRATION TEST PROMPTS  -  MODULE WISE
================================================================================
File : HMS_py/MODULE_FIX_PLANS/MIGRATION_TEST_PROMPTS.txt
Date : 2026-09-30
Purpose: Har module ke liye ek READY-TO-PASTE text prompt. AI agent / debug
         session me ek prompt copy karo, wo uska migration test khud karega
         aur neeche diye gaye output format me report dega.

Kaise use karna hai
-------------------
1. Header ka "COMMON RULES" + "COMMAND CHEATSHEET" har prompt ke saath
   copy-paste hota hai (module block already unhe include karta hai).
2. Ek session me ek hi prompt. Doosre module ka prompt alag session me.
3. Prompt ke end me `[END PROMPT-NN]` tak hi paste karna hai.

Reference docs (har prompt isi ko cite karta hai)
-------------------------------------------------
- Module manual (2026) : HMS_REVERSE_ENGINEERING/MODULE_MANUALS_2026/<NN_Module>/
                         README.md / FRONTEND.md / BACKEND.md / DATABASE.md
                         TEST_PLAN.md / TEST_RESULTS.md / _logic.json
- Test plan master     : .../00_Instructions/TEST_PLAN_MASTER.md   (layers + KI log)
- Test log             : .../00_GLOBAL/RUN_TEST_LOG.md
- VB6 RE manual        : HMS_REVERSE_ENGINEERING/<NN folder>/module_manual.md
- VB6 source (truth)   : implemented/HMS2526/serialkey/PROJECT2/PROJECT/*.frm|.bas
- Menu tree            : core/mdi_menu.json   |  runtime: ui/shell.py _form_registry()

--------------------------------------------------------------------------------
COMMON RULES (har module prompt me same)
--------------------------------------------------------------------------------
- Live SQL Server DB = source of truth. VB6 form/event = behavior reference.
- Koi table/column NAHI ghadna. Agar table live DB me absent hai -> BLOCKED
  likho, safe viewer / no-op rakho. "Table missing" ko crash me mat badlo.
- Read-only DB check chalega. Likhne wale test yaft rollback/snapshot se hon.
- Sirf us module ke files touch karo. Doosre module ka code/registry entry
  mat badlo (parallel sessions chal rahe hain).
- Har fix ke saath focused regression test. Bina test ke "DONE" mat likho.
- Evidence har baat ke saath: file:line, SQL result, test name + command.
- "Coming Soon" (_coming_soon) leaves = documented gap, bug nahi - par unhe
  list karna zaroori hai, chup mat raho.

COMMAND CHEATSHEET
--------------------------------------------------------------------------------
# pytest wale commands ka cwd = HMS_py\HMS_py  (jis me tests/ ui/ core/ hain)
python -m pytest tests/unit -q                                   # L1 unit, no DB
python -m pytest tests/database -q                               # L2 live DB (rollback)
python -m pytest tests/test_front_office.py -q                   # L2b FO flows
python -m pytest tests/test_wave_ui_forms.py tests/test_ui_walkthroughs.py -q   # L3 offscreen UI
python tests/database/<file>.py                                  # L2c proof script

# ye dono cwd = toplevel (HMS_py\ , jahan HMS_py package hai)
python -m HMS_py.tools.manual_pipeline.run_module_tests --module <NN_Module>    # L1..L3 + TEST_RESULTS.md
python -m HMS_py.tools.manual_pipeline.capture_module --module <NN_Module>      # L4 live desktop capture
python -m HMS_py.tools.manual_pipeline.check_manual --module <NN_Module>

OUTPUT FORMAT (har prompt ka expected jawab)
--------------------------------------------------------------------------------
Module            : <NN_Name>
VB6 object(s)     : <frm/bas name + event>
Python file(s)    : <ui/...py:line, core/...py:line>
DB check          : <table -> rows / MISSING>
Menu registry     : <leaf -> opener | _coming_soon | None>
Test run          : <command> -> <pass/fail counts>
Root cause        : <why behaviour alag thi (ya "parity OK")>
Fix / Gap         : <fix + test file, ya BLOCKED + reason>
Status            : PASS | PARTIAL | BLOCKED | FAIL
Risk              : <agla kadam / kis module pe impact>
