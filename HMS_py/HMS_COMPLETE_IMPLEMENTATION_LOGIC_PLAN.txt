============================================================ 0. PURPOSE
============================================================

This document is the implementation blueprint for rebuilding/debugging
the complete Analysis HMS project from the legacy VB6 HMS.bas behavior.

Primary target: Windows local HMS application Python backend
React/HTML/CSS frontend SQL Server 2008 R2 compatible database

CORE PRINCIPLE:

    UI -> API -> SERVICE/BUSINESS LOGIC -> REPOSITORY/SQL -> DATABASE

Never put business rules only in the frontend. Never execute raw SQL
from the frontend. Every important transaction must be validated again
in the backend.

The legacy system is centered around: USERMAST / permissions COMPANY /
SITE / ENVIRO BOOKING GUESTPROF GUESTFOLIO ROOMMAST ROOMOCC PAYCHARGE
POS/KOT/SunTran STOCK LEDGER NIGHTAUDITLOG

============================================================ 10.
CHECK-IN MODULE
============================================================

THIS IS A CRITICAL TRANSACTION.

FRONTEND: Reservation lookup Guest Room Rate Plan Adults Children
Arrival Departure Company Travel Agent Market Segment Business Source
Advance Remarks

API: POST /api/front-office/checkin

BACKEND FLOW:

1.  Authenticate.
2.  Check permission.
3.  Validate site.
4.  Validate booking if booking-based.
5.  Validate guest.
6.  Validate target room.
7.  Recheck room availability.
8.  Begin transaction.
9.  Create/update GuestFolio.
10. Create RoomOcc.
11. Create profile detail rows if required.
12. Post initial advance/charge if configured.
13. Update reservation conversion state.
14. Commit.
15. Return Folio/Room/Guest information.

TRANSACTION:

BEGIN TRANSACTION

GuestFolio INSERT RoomOcc INSERT Profile detail INSERT Initial PayCharge
INSERT if required Booking conversion UPDATE

COMMIT

ON ERROR: ROLLBACK

RateCode RoomRate ChkInDate ChkInTime Adult Children DepDate DepTime
PlanCode PlanAmt Site_Code LogSite_Code

GUESTFOLIO CORE: DocId FolioNo MFolioNo GuestProf Name NoDays Company

LogSite_Code

============================================================ 13. CHARGE
POSTING MODULE
============================================================

TABLE: PayCharge

COMMON TYPES: Room Rent Food Laundry Other Charge Discount Tax Payment
Adjustment POS transfer

BALANCE:

Balance = SUM(AmtDr) - SUM(AmtCr)

QUERY:

SELECT SUM(ISNULL(AmtDr,0)) Debit, SUM(ISNULL(AmtCr,0)) Credit,
SUM(ISNULL(AmtDr,0))-SUM(ISNULL(AmtCr,0)) Balance FROM PayCharge WHERE
FolioNoDocId=?

RULE: Amount must be calculated/validated server-side. User cannot send
arbitrary debit/credit without validation.

============================================================ 39. NIGHT
AUDIT — MASTER LOGIC
============================================================

NIGHT AUDIT IS THE MOST CRITICAL DAILY PROCESS.

PRE-CONDITION: Normal billing must be stopped/controlled. User must have
Night Audit permission. Business date must match expected audit date.

FLOW:

START | Acquire audit lock | Validate user | Validate date | Load ENVIRO
| Pending KOT check | Pending POS bill check | No-show | Room rent |
POS/F&B revenue | Account posting | Token reset | Audit reports |
NightAuditLog | Business date transition | Release lock | END

============================================================ 40. NIGHT
AUDIT — DATE VALIDATION
============================================================

Input: Audit Date

Validate against: Current Business Date / Enviro configuration

If mismatch: STOP

Message: Check Audit Date or contact administrator.

============================================================ 41. NIGHT
AUDIT — KOT CHECK
============================================================

Read:

SELECT KOTAtNightAudit FROM Enviro WHERE LogSite_Code=?

If enabled: search pending KOT.

If pending: show outlet/table/token/KOT details block or warn according
to legacy rule.

============================================================ 42. NIGHT
AUDIT — POS BILL CHECK
============================================================

Read:

SELECT POSBillAtNightAudit FROM Enviro WHERE LogSite_Code=?

If enabled: find pending/unsettled POS bills.

If pending: block or warn according to legacy rule.

============================================================ 43. NIGHT
AUDIT — NO SHOW
============================================================

Read: NoShowAtNightAudit

If enabled:

Find today’s arrivals where: Cancel <> ‘Y’ AND no GuestFolio/check-in
exists

Mark:

Cancel=‘Y’ CancelDate=GETDATE() U_Name=‘NOSHOW’

Never mark a guest as no-show if a valid check-in exists.

============================================================ 44. NIGHT
AUDIT — ACTIVE ROOMS
============================================================

Source: RoomOcc GuestFolio RoomCat RevMast

Find: ChkOutDate IS NULL Site matches

For each active stay: determine room rate determine plan determine tax
determine discount determine complimentary status determine revenue
account determine charge code

============================================================ 45. NIGHT
AUDIT — ROOM RENT POSTING
============================================================

CONFIG: RoomChrgPostingType

For each eligible room:

1.  Check whether today’s room charge already exists.
2.  Calculate correct amount.
3.  Determine revenue code/account.
4.  Determine tax.
5.  Determine discount/RODISC.
6.  Post PayCharge.
7.  Record source reference.
8.  Mark posting successful.

IDEMPOTENCY:

Before insert: search PayCharge for same: Folio BusinessDate
ChargeType=‘RC’ Source=‘NIGHT_AUDIT’

If already posted: DO NOT INSERT AGAIN.

============================================================ 46. NIGHT
AUDIT — POS / F&B REVENUE
============================================================

Read: SunTran RevMast Depart POS tables

Group: revenue code outlet business date

Post: required revenue/account entries

Keep: POS document reference source outlet source date posting user
audit run id

============================================================ 49. NIGHT
AUDIT — LOG ============================================================

INSERT INTO NightAuditLog ( DateChngFrom, DateChngTo, StartNightAudit,

============================================================ 50. NIGHT
AUDIT — REVERSE
============================================================

Reverse Night Audit must NOT blindly delete all transactions.

Recommended:

Audit Run | Load postings generated by RunID | Validate no later
dependent transaction | Create reversals | Reverse only generated
entries | Restore business date according to rules | Audit reversal

If legacy database has no RunID: create a controlled migration
wrapper/table for new HMS_py rather than relying only on date/time.
