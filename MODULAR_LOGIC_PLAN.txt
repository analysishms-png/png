MODULE 1: MENU SYSTEM LOGIC (User_Module + User1 + menuHelp)
-----------------------------------------------------------------
SOURCES:
- User_Module table: Stores menu structure (code, name, flag, srno, Module_Name)
- User1 table: User rights mapping (USER_NAME, SRNO -> links to User_Module.srno)
- menuHelp table: Per-user/module rights (Option, Param_Str, Flag, Module_Name, Opt1-Opt4)
- Analysis.ini key 9: Sidebar module order (#-delimited)

FLAG VALUES (from VB6 decompilation evidence):
- flag='9': Sidebar root node (appears in Analysis.ini key 9 list)
- flag='1': Submenu header / parent item (creates dropdown in menubar)
- flag='0': Leaf child item (appears under flag=1 parent with same 'code')
- flag='E': Entry/form access (in menuHelp Param_Str)
- flag='R': Report access (in menuHelp Param_Str)
- flag='N': Node/header (in menuHelp)
- flag='V': Hidden (in menuHelp - never shown)

MENU NAVIGATION FLOW:
1. Login -> Company select (frmCompany) -> Main window
2. Main window sidebar = Analysis.ini key 9 list, filtered by User_Module flag=9
3. Menubar groups = DISTINCT Module_Name from User_Module (flag<>'9'), ordered by MIN(srno)
4. Each group = menu title + item list built from _group_rows + _build_dropdown
5. Nesting logic: flag=1 item => submenu; same-code flag=0 rows => children of that parent
6. Rights check: User1 rows for username -> if NONE, full access; else menu leaf srno must be in User1 set

USER RIGHTS LOGIC (menu.py:menu_name_allowed):
- If User1 has NO rows for user => full access (SA 617/617 case)
- If User1 has rows => menu leaf must map to User_Module.srno recorded for this user
- Normalization: strip "- HMS_py", "- HMS", remove parens, lowercase, collapse spaces

MODULE 2: MENUHELP RIGHTS SYSTEM (menuHelp table)
--------------------------------------------------
SOURCE: FODER\FaVoucher.bas + MainLib.bas decompilation evidence

TABLE STRUCTURE:
- menuHelp: UserName, CompCode, [Option], Param_Str, Flag, Module_Name, Opt1, Opt2, Opt3, Opt4

RIGHTS PATTERN (Param_Str - 4 characters):
- Position 1: Add (A) or no-add
- Position 2: Edit (E) or no-edit
- Position 3: Delete (D) or no-delete
- Position 4: Print (P) or no-print

DEFAULT RIGHTS (missing row/leaf):
- Full access => "AEDP"
- If row exists => use Param_Str value, default "AEDP" if empty

PERMISSION CHECK FUNCTIONS:
- flag_for(caption, username): Returns E/R/N/V or None
- rights(username, caption): Returns Param_Str string
- can(username, caption, right): True if right in Param_Sr (case-insensitive)
- can_open(username, caption): True if flag!=V; also checks AEDP for leaf access

NO menuHelp row for user => full access (mirrors User1 pattern in menu.py)

MODULE 3: master LIST FROM DATABASE (User_Module table)
--------------------------------------------------------
EXTRACTED FROM: SQL query evidence + VB6 decompiled structure

USER_MODULE COLUMNS (from decompiled HMS.bas + Python port):
- code: Menu control name / code (e.g., "FA", "Mast", "FrontDesk")
- name: Menu display name (e.g., "Session Master", "Tax Master", "User Master")
- flag: Visibility/role flag ('9'=sidebar root, '1'=submenu, '0'=leaf)
- srno: Sort order number (used for nesting and menubar ordering)
- Module_Name: Parent module/category group (e.g., "Front Office", "Finance", "POS")

SAMPLE QUERIES (from core\menu.py):
1. roots(): SELECT code, name, srno FROM User_Module WHERE flag='9' ORDER BY srno
   => Returns sidebar root nodes for Analysis.ini key 9

2. _group_rows(module_name): SELECT code, name, flag, srno FROM User_Module WHERE Module_Name=? AND flag<>'9' ORDER BY srno
   => Returns module items for a given category

3. Menu building: Distinct Module_Name values determine menubar groups
   => Groups: Front Office, General Setup, Finance & Reports, POS & Banquet, HR & Members, Inventory & Reports

USER1 RIGHTS TABLE:
- USER_NAME: Login username (e.g., "SA", "PYADMIN")
- SRNO: Maps to User_Module.srno for rights assignment

SAMPLE DATA PATTERNS (from fix plans and project map):
- flag=9 roots: Typically 15-20 top-level sidebar entries
- Module_Name groups: ~10 distinct categories
- Per-group: 3-15 items (flag=1 parent + flag=0 children)
- Example: "GENMas" flag=1 (43) -> flag=0 children (44-47) = "Tax Master" sub-items
