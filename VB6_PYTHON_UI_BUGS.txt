VB6 vs Python UI: Code-by-Code Comparison & Bug Analysis
================================================================

DATE: 2026-09-27
PROJECT: HMS (Hotel Management System) - VB6 to Python Migration
SCOPE: Comparative analysis of VB6 Forms vs PyQt6 Python UI equivalents

==============================================================================
EXECUTIVE SUMMARY
==============================================================================
This report documents code-level differences and identified bugs between
original VB6 forms and their Python PyQt6 equivalents. The analysis covers
321 VB6 .frm forms vs 82 Python UI modules.

Key Findings:
- 110 forms: FULL port (comparable fields/actions)
- 124 forms: PARTIAL (shared/simplified screens)
- 10 forms: WRONG_TARGET (menu opens wrong form)
- 71 forms: COMING_SOON (DB-blocked or documented skip)
- 5 forms: MISSING (artifacts only)

Total function coverage: ~13.8% (290 PORTED / ~550 PARTIAL / ~5,020 MISSING)

3. SPECIFIC BUGS IDENTIFIED
==============================================================================

BUG #1: TXTADJ_AMT Numeric Validation Loss
------------------------------------------------------------------------------
VB6 (TXTADJ_AMT_Validate event):
- Validates amount against pending adjustment amount
- Checks: CDbl(Val(CStr(Me.FgridAdjust.TextMatrix))) < CDbl(Val(var_158))
- Shows message: "Amount is Greater Then Pending Adj.Amt. You Can Adjust Only X"
- Uses global_56 and global_60 for tracking
- KeyPress event restricts input to numbers only

Python (FaAdjustWindow._save):
- Simply does: float(self.txt_amt.text() or 0)
- No validation against pending amounts
- No numeric key restriction
- Only catches ValueError on conversion

BUG #2: DataCombo Replacement Missing Functionality
------------------------------------------------------------------------------
VB6 DataCombo TXT_ACCOUNT:
- BoundText property shows selected account name
- Dropdown with search/filter functionality
- Bound to ACGROUP table via Proc_183_43_EF7D54
- Index changed events populate other fields

Python QLineEdit:
- Placeholder text only: "Enter SubCode"
- No dropdown/filter capability
- No BoundText equivalent
- Text changed signals don't trigger equivalent logic

BUG #3: MSFlexGrid Row/Column Behavior Differences
------------------------------------------------------------------------------
VB6 MSFlexGrid:
- TextMatrix property: (row, col) indexing
- Rows property: includes fixed rows count
- Redraw property: True/False for flicker control
- CellLeft, CellTop, CellWidth properties
- Row selection: Me.FgridAdjust.Row = value

Python QTableWidget:
- setItem(row, col, QTableWidgetItem) pattern
- rowCount property: only data rows (no fixed rows concept)
- No direct equivalent of TextMatrix
- setRedraw(True/False) instead of Redraw property
- CurrentRow / currentRowChanged signal

BUG #4: Error Handling Paradigm Shift
------------------------------------------------------------------------------
VB6 Error Handling:
- On Error Goto loc_1487774 pattern throughout
- Error numbers used for different error paths
- Resume Next / Resume 0 patterns
- Global error handler: Proc_183_57_104AA84
- Error restoration: RollbackTrans on failure

Python Error Handling:
- try/except blocks only
- No error numbering system
- QMessageBox for user errors
- No transaction rollback equivalent (auto-commit)
- Exception details shown via QMessageBox.critical

BUG #5: Form Resize Behavior
------------------------------------------------------------------------------
VB6 Form_Resize:
- Recalculates LblFormCaption.Left = 0
- LblFormCaption.Width = var_90 (dynamic)
- Method_arg_100 called with var_90

Python FaAdjustWindow:
- Fixed resize(800, 500) in __init__
- No Form_Resize event handler
- Layout-managed widgets expand/shrink automatically
- Missing: Caption auto-resizing logic

BUG #6: Tab Order Differences
------------------------------------------------------------------------------
VB6 TabIndex properties explicitly set:
- TXT_DATE: TabIndex=0
- TXT_ACCOUNT: TabIndex not explicitly set (after DataCombo)
- TXT_Group: TabIndex not set
- BTSADJUST: TabIndex=22
- ADJ_OK: TabIndex=9
- ADJ_CANCLE: TabIndex=8
- BtnAdd: TabIndex=29
- BtnFill: TabIndex=28
- BtnExit: Not explicitly set

Python:
- Qt handles tab order via focusNextChild() / setTabOrder()
- No explicit TabIndex properties
- Order depends on creation sequence in code
- May not match VB6 tab order

MISSING FUNCTIONALITY FROM VB6 -> PYTHON PORT
==============================================================================

1. No equivalent of VB6 Proc_183_* function calls
   - 50+ custom functions in HMS.bas not ported
   - Method_arg_*, LateIdCallSt, Proc_183_* patterns lost

2. No transaction management equivalent
   - VB6: BeginTrans/CommitTrans/RollbackTrans
   - Python: Auto-commit only, no explicit transaction control

3. No DataCombo/DropDown replacement
   - 30+ DataCombo controls lost functionality
   - Search/filter/filter cancellation missing

4. No MSFlexGrid replacement
   - 20+ MSFlexGrid usages for data display
   - Virtual list mode, unbound grid behavior lost

5. No form-level global variables
   - VB6: global_56, global_60, global_68, etc. throughout
   - Python: No global state equivalent (use core modules instead)

6. No equivalent of frx (frame) picture resources
   - VB6: DisabledPicture, Picture properties
   - Python: QIcon or stylesheet-based buttons

7. No menu/vbar integration
   - VB6: Forms as MDIChild with specific menu leaves
   - Python: Standalone windows, no menu integration

ADDITIONAL BUGS FROM ADJUSTMENT DELETE COMPARISON
==============================================================================

BUG #7: Account Combo Data Population
------------------------------------------------------------------------------
VB6 (FaAdjust.frm BtnAdd UnknownEvent):
- Proc_183_43_EF7D54 called to populate TXT_Group DataCombo
- SQL: "SELECT GroupName,GroupCode FROM ACGROUP WHERE (LOGSITE_CODE=... OR LOGSITE_CODE='HO') ORDER BY GroupName"
- BoundText property shows selected group name
- BoundIndex shows selected GroupCode

Python (AdjustmentDeleteWindow._load_accounts):
- db.query("SELECT SubCode, Name FROM SubGroup ORDER BY Name")
- QComboBox.addItem((r[1] or "").strip(), r[0]) - displays Name, stores SubCode
- currentData() used to retrieve SubCode
- BUG: Uses "SubGroup" instead of "ACGROUP" - different table!
- VB6: ACGROUP table with GroupName/GroupCode
- Python: SubGroup table with Name/SubCode
- Result: Different data set, potential missing accounts

BUG #8: Delete Confirmation Logic Loss
------------------------------------------------------------------------------
VB6 (FaAdjust.frm ADJ_CANCLE_Click):
- Complex validation: checks global_68, global_60 for pending amounts
- var_144 = Format(var_168, "0.00") - difference calculation
- MsgBox with detailed info: "* Amount Already Adjusted *"
- Multiple global variable checks before allowing cancel

Python (AdjustmentDeleteWindow._delete):
- Simple check: if r < 0: warning "Pehle row select karo."
- No pending amount validation
- No difference calculation between credited/debited amounts
- No detailed confirmation message with DocId/SNo details
- Missing: "Entries Not Found" type validation

BUG #9: Grid Filling Logic Differences
------------------------------------------------------------------------------
VB6 (FaAdjust.frm BTNFILL_Click):
- Complex fill logic: queries LEDGERM table for existing entries
- Checks: CVar(var_90) < var_94.Fields.Item("Credit").Value
- Builds grid rows: var_244 & var_94.Fields.Item("V_Type").Value etc.
- Conditional loading based on existing credit amounts
- var_90 = CSng(var_204) - currency conversion

Python (_fill method):
- Simple db.query + _fill_grid call
- No conditional loading based on existing credits
- No var_90 / var_204 currency tracking variables
- No "Short Date" format constant var_100 = "Short Date"
- Simplified: just fills whatever is in database

BUG #10: Error Message Localization Missing
------------------------------------------------------------------------------
VB6 Error Messages:
- "* Amount Already Adjusted *"
- "* No Entries to Adjust *"
- "Amount is Greater Then Pending Adj.Amt. You Can Adjust Only X"
- "Here" appended to messages
- Uses VB6 message box constants: &H40, &H10

Python Error Messages:
- QMessageBox.information(self, "Saved", "Adjustment saved!")
- QMessageBox.warning(self, "Select", "Pehle row select karo.")
- QMessageBox.information(self, "Fill", "No Record Found to Fill")
- No localized/constant message patterns
- No &H40 / &H10 hex color constants
- Different message box button sets (StandardButton.Yes vs vbYesNo)
